# Реестры счетов

SPA для ведения реестров счетов и переписки организации. Управление счетами, частичная оплата, отметки к оплате, история изменений, печать, расчётные счета с остатками, входящие и исходящие письма с цепочками переписки, ролевая модель, уведомления.

Репозиторий: <https://github.com/Yogurt7v/Table>

## Ролевая модель

Пять ролей в коллекции `organization_users`:

| Роль          | Создание | Редакт.                      | Удаление | Перенос | История | Оплата (paid) | Отметки к оплате | Файлы |
| ------------- | -------- | ---------------------------- | -------- | ------- | ------- | ------------- | ---------------- | ----- |
| **admin**     | ✓        | ✓                            | ✓        | ✓       | ✓       | ✓             | просмотр         | ✓     |
| **moderator** | ✓        | ✓                            | ✓        | ✓       | ✓       | ✓             | просмотр         | ✓     |
| **user**      | ✓        | ✓ (кроме `paid`/`paid_date`) | ✗        | ✗       | ✗       | ✗             | ✗                | ✓     |
| **boss**      | ✗        | ✗                            | ✗        | ✗       | ✗       | ✗             | **создание**     | ✗     |
| **guest**     | ✗        | ✗                            | ✗        | ✗       | ✗       | ✗             | ✗                | ✗     |

- **boss** не видит колонки `paid`/`paid_date`, но может ставить мягкие отметки к оплате.
- Если счёт уже оплачен модератором, босс видит «Уже оплачено» вместо кнопок отметки.
- **moderator** может фактически проводить оплату (устанавливать `paid = true`).

**Почтовые права** — отдельный флаг `can_view_mails` в `organization_users` (выдаётся в панели администратора): без него страница `/mail` и вкладка «Архив писем» недоступны независимо от роли.

## Функциональность

### Счета

- **Дата** — выбор дня через DatePickerInput; все счета и остатки привязаны к дате
- **Счета** — группировка по объектам учёта, внутри — по контрагентам
- **Inline-форма** — быстрая inline-форма создания счёта с автодополнением контрагентов
- **Drag & drop** — перетаскивание строк контрагентов для изменения порядка
- **Частичная оплата** — модальное окно с суммой и комментарием
- **Мягкие отметки** — boss помечает счета к оплате, moderator/admin видят и обрабатывают
- **Поиск** — полнотекстовый поиск по всем счетам организации (с автоподсветкой)
- **Скрыть оплаченные** — чекбокс, скрывающий оплаченные счета (доступен admin, moderator, boss)
- **Печать** — CSS Print Preview с группировкой по объектам учёта
- **Экспорт в Excel** — выгрузка реестра счетов
- **Файлы** — прикрепление и просмотр файлов к счетам
- **История** — просмотр изменений счёта с предыдущими значениями
- **Перенос** — перемещение счёта между объектами учёта
- **Копирование** — создание счёта на основе существующего
- **Настройка колонок** — модальное окно выбора видимых колонок таблицы
- **Адаптив** — на узких экранах таблица заменяется карточками

### Переписка (`/mail`)

- **Реестр писем** — входящие и исходящие, таблица с фильтрами и поиском
- **Цепочки переписки** — связи «родитель → ответ» через `mail_relations`; дерево цепочки строится автоматически
- **Связывание** — при создании письма можно указать родительское (по номеру или из списка)
- **Файлы** — прикрепление файлов к письмам
- **История** — аудит изменений писем
- **Архив** — мягкое удаление с восстановлением; восстановление сохраняет исходного автора
- **Печать переписки** — печать всей цепочки целиком
- **Настройка колонок** — выбор видимых колонок
- **Адаптив** — карточки на узких экранах

### Общее

- **Уведомления** — в реальном времени при создании/изменении/оплате счетов и писем
- **Личный кабинет** — смена пароля, настройки
- **Панель администратора** — организации (создание/редактирование/удаление с проверками), пользователи и роли, почтовые права, архив счетов, архив писем

## Разработка

### Команды

| Команда               | Описание                                         |
| --------------------- | ------------------------------------------------ |
| `pnpm dev`            | Запуск Vite dev-сервера                          |
| `pnpm dev:all`        | Фронт + PocketBase одной командой (concurrently) |
| `pnpm pb`             | Запуск PocketBase (порт 8090)                    |
| `pnpm build`          | `vitest run` (prebuild) + `tsc -b && vite build` |
| `pnpm build:portable` | Сборка в `builds/table-<дата-время>`             |
| `pnpm lint`           | Проверка ESLint                                  |
| `pnpm typecheck`      | `tsc --noEmit`                                   |
| `pnpm test`           | `vitest run`                                     |
| `pnpm test:watch`     | `vitest` (watch)                                 |
| `pnpm test:coverage`  | `vitest run --coverage`                          |
| `pnpm test:e2e`       | Playwright e2e (сам поднимает pb + vite)         |
| `pnpm test:e2e:ui`    | Playwright в UI-режиме                           |
| `pnpm humantest`      | Сквозной сценарий пользователя (human-flow)      |
| `pnpm format`         | `prettier --check .`                             |
| `pnpm format:write`   | `prettier --write .`                             |
| `pnpm start`          | Прод-запуск PocketBase на `0.0.0.0:8090`         |

Порядок перед коммитом: `pnpm lint && pnpm typecheck && pnpm build`.

`pnpm build` обязателен: `typecheck` гоняет корневой `tsconfig.json` через `tsc --noEmit`, а `build` — `tsc -b` по project references (`tsconfig.app.json`). Опции в них не совпадают, и `build` находит ошибки, которые `typecheck` пропускает.

### Соглашения

- **TypeScript strict mode** — `strict: true`, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`, `erasableSyntaxOnly`
- **Путевой алиас** — `@/` → `src/`
- **Импорты** — `import type` для type-only импортов
- **ESLint** — ts recommended + react-hooks + react-refresh
- **Prettier** — semi, singleQuote, trailingCommas all, printWidth 100, tabWidth 2
- **UI-тексты** — на русском
- **Менеджер пакетов** — pnpm (не npm)

### Тестирование

**Юнит-тесты** — Vitest + jsdom:

- 103 файла, ~1300 тестов; файлы рядом с кодом: `*.test.ts`, `*.test.tsx`
- Setup-файл `src/test-setup.ts` импортирует `@testing-library/jest-dom` и мокает `window.matchMedia`
- Запуск: `pnpm test` или `pnpm test:watch`

**E2E** — Playwright:

- 13 сценариев в `e2e/specs/`: авторизация, счета и их создание, оплаты, переносы, файлы, архив, права, поиск и фильтры, уведомления, админка, расчётные счета, сквозной сценарий пользователя
- `playwright.config.ts` сам поднимает PocketBase (`pnpm pb`) и Vite (`pnpm dev`) перед прогоном
- Запуск: `pnpm test:e2e` (обычный), `pnpm test:e2e:ui` (интерактивный), `pnpm humantest` (сквозной сценарий)
